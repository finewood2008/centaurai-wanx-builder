# WANX Builder 0.5.0：专家标准应用与对话修改

用户先选择一个标准应用，再用 Builder 对话修改用途、任务功能和 UI。构建物是私人 Agent 应用，主要通过任务界面执行；执行记录、原生确认和交流按需展开。

## 完整目录与分类

2026-10-12 读取内置源码及实际 SkillHub 分页目录，取得 27 个内置专家配置、55 个市场专家的完整方法，共 82 个条目。逐项映射清单见 `expert-app-inventory.md`。用户登录后重新读取所连接盒子的内置目录、市场目录及已发布专家；快照只用于浏览，不代表当前账号依赖已经可用。

## 应用创建与能力继承

创建时通过 WANX 原生接口实例化已选专家，复制其已有技能到原生技能包；Builder 不生成执行文件。标准应用定义引用技能包和原生专家模板，试用及私人实例沿用原专家资源的原生初始化。原生账号权限、工具审批、能力状态核验继续生效。

正式草稿直接从所选应用定义初始化，避免先写通用应用、再以没有构建会话的方式覆盖草稿。Builder 对话读取当前定义、模板选择和来源专家方法，修改同一个 applicationId。只有 Craft 可以写应用定义；Ask/Plan 的权限不扩大。

## UI 与实际任务

v2 增加八类任务布局，以及 table/chart/board/checklist 组件，保留旧布局和已发布实例。任务按钮调用原生 Agent 对话运行通道，输入以数据传入；进度、结果、确认与执行记录读取原生状态。

结构化组件读取 outputs JSON：表格使用 columns/rows，图表只接受实际数值 metrics，方案与清单读取 items。不渲染任意 HTML/JavaScript，坏格式显示修复原因，示意预览不读取真实结果或执行任务。

生成应用默认显示任务工作区；交流和执行记录不是必需的主界面。原生执行确认出现时自动展开记录区，用户可以完成确认。

## 应用中心与验证

草稿、不可变版本、试用、构建、发布和私人实例继续由应用中心管理。专家模板引用只影响新私人实例初始化；更新保留用户文件、记忆和任务记录。

验证分为完整目录/契约验证、界面验证、隔离原生 WANX 的生命周期验证，以及真实盒子的业务验收。目录全量梳理不表示 82 个专家的全部业务任务都已实测；每个实例试用和交付仍核验自己的依赖与实际任务证据。
